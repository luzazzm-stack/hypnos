Memory that sleeps, and can show its evidence

Spec v0.3 for a long-running LLM agent. It takes the original "AI that lives and sleeps like a human" idea, keeps the parts that can be built and tested, and drops the rest. One person can build this with an LLM API and a database.

Core who I am, goals, standing beliefs

About one page. Always loaded on wake. Built on the first sleep, then rebuilt weekly from the period summaries and the small topic summaries (from sessions until the first period exists). Never edited in place, so errors cannot pile up inside it.

Period summaries one per calendar week

What the agent worked on, what changed, what it learned. Written once a week has closed with sessions on at least three dates.

Session summaries one per sleep cycle

Written during sleep from that session's episodes only. A calendar day can hold several sessions. Each sentence keeps the ids of the facts or episodes it came from.

Episodes what happened, predictions, outcomes, lessons

The working unit of memory. Structured, not just prose. Every claim cites a span of the raw log, and a checker pass has confirmed the span supports it.

Raw log everything, append-only, never rewritten

Every message, tool call and observation with a timestamp. It is the ground truth. Summaries are an index into it, not a replacement for it.

Recall starts at the top and digs down only as far as the question needs. Tap a layer to see what it holds. Alongside these time layers, every topic is also kept at three sizes (small, medium, big), each written from the topic's verified facts, with the topic's own original log underneath as the fourth step.

Keep, change, ditch

The test for each idea was simple: does it add a capability that can be measured, at a cost one person can pay? Ideas that only made the system look more human failed that test.

Keep

Summary tree that expands on demand
The strongest idea in the design. Small summary first, then medium, then big, then the exact event. v0.2 keeps this per topic as well as per time period.
Every summary points to its evidence
Lets the agent tell "I remember X" apart from "my summary says X, let me check". This is what most agent memory lacks.
Sleep as a separate offline phase
Consolidation is slow and costly. Doing it while the agent is not working keeps the awake loop fast.
Sleep does more than summarise
Linking to old memories, spotting contradictions, and deciding what to forget. These are rare in current systems.
A wake routine
Load core, goals and open problems before anything else. This is where continuity between sessions comes from.
A fast layer under the reasoner
Kept, but moved to phase 3 and given a narrower job. See "Change".

Change

Sleep trigger
Was: context at 90 to 95 percent. Now: context near 75 percent, or a task boundary, or idle time. At 95 percent there is no room left to finish cleanly.
"Summarise the day"
Now: extract structured episodes (event, prediction, outcome, lesson), then check each claim against the log.
Jev as reflexes
Now: Jev answers every bounded, typed question: as a gate while awake ("does this need a memory lookup?") and as a judge during sleep (verify, link, topic, entity, contradiction type, importance). At a few hundred ms over a hosted API it cannot do balance. Each question starts in shadow mode next to an LLM and goes live only when it agrees.
100 PB of storage
Now: SQLite or Postgres plus a vector index. Years of text experience fit in gigabytes.
"Remember everything"
Now: log everything, but index selectively. Low-value memories leave the index and stay in the log.
Pure top-down recall
Now: top-down first, with a fallback search over the raw log. If a summary dropped a detail, top-down alone can never find it.

Ditch

DNA storage
Slow to write, slow to read, no random access. Storage size was never the bottleneck.
Fixed 12 to 16 hour sessions
Context fills by tokens, not hours. A body clock adds rules without adding ability.
Humanoid body and balance control
A separate field with its own hardware. Robotics labs already run layered fast and slow control.
Simulated universe, civilisation of agents
Cannot be measured yet. Prove one agent's memory works first.
Nightly weight updates
Parked, not deleted. It is the real open research problem, and it needs the memory layer working first as its data source.
"Lives like a human" as the goal
Not testable. The goal is now a number: recall accuracy over long gaps, at a known cost.

The claim this spec tests

An agent with an evidence-linked summary tree and an offline consolidation phase will, after many sessions, answer questions about its own past more accurately, with fewer confident false memories, and at similar or lower cost per question than the two things agents do today: flat vector search over old chunks, and a single rolling summary.

If that is false, the architecture is not worth its complexity. Write that down before running anything.

Data model

One node type covers every level above the raw log. Sketch, not strict JSON:

node = {
  id:          "ep_s000412_03",
  level:       "episode",            # core | period | session | episode | topic
  topics:      ["topic_storage_sim"],
  text:        "Tested config X on the storage sim. Predicted +12% efficiency. Got -3%.",
  facts: [                           # episodes only; each fact is checkable
    { id:    "ep_s000412_03#f2",
      claim: "Config X reduced efficiency by 3%",
      kind:  "outcome",              # event | prediction | outcome | decision | lesson | belief_revision
      evidence: ["log:48211-48390"], # spans in the raw log
      superseded_by: null }          # a fact id
  ],
  claims_extracted: 11,              # counted before verify
  claims_rejected:  2,               # dropped by verify
  confidence:  0.82,                 # (extracted - rejected) / extracted
  children:    [],                   # one level down; empty for episodes
  parents:     ["ses_000412"],
  importance:  0.6,                  # scored once at creation
  created:     "2026-09-21T23:04Z",
  last_used:   "2026-10-02T09:15Z",
  recalled_count: 4,
  useful_count:   3,                 # times it changed what the agent did
  status:      "active"              # active | archived | superseded
}

summary = { id: "topic_storage_sim.medium", level: "topic", resolution: "medium",
            sentences: [ { text: "...", cites: ["ep_s000412_03#f2"] } ] }

link = { from: "ep_...#f2", to: "ep_...#f4", type: "contradicts", note: "..." }

log_row   = { seq: 48211, ts: "...", role: "tool", content: "...(redacted)" }
watermark = { consolidated_upto: 48390 }

Two rules that carry the design. A summary is always regenerated from its sources (time nodes from their children, each topic size from the topic's facts), never edited from its own previous text. And nothing is deleted: forgetting removes a node from the index, not from storage, and its parent keeps the link.

Awake

Wake routine

Load the core node, the last few session summaries, the small summaries of the topics the wake note names, and finally the wake note itself (open problems, unfinished work, plans). That is the whole starting context. Everything else is fetched when needed.

Recall

def recall(query, token_budget, start="topic_small"):
    # 1. search the small, compressed levels first (the gate may pick another start)
    frontier = search(query, levels=START[start], k=5)
    found = []

    # 2. dig down only where it looks promising
    while frontier and token_budget.left():
        node = frontier.pop_best(query)
        found.append(node)
        if sufficient(query, found):          # cheap model call or the gate
            break
        frontier.add(zoom_in(node))            # small -> medium -> big -> episodes
        frontier.add(linked(node, types=["same_entity", "supersedes"]))

    # 3. safety net: what did the summaries drop?
    if not sufficient(query, found):
        found += vector_search(raw_log_chunks, query, k=5)

    # 4. return superseded facts together with their replacements, flagged
    found = attach_replacements(found)
    return found, evidence_spans(found)

The evidence rule

When a remembered fact matters to a decision, the agent opens the cited log span before acting on it. When it only has a summary and has not checked, it says so. This is cheap, and it is the behaviour the false-memory metric rewards.

When to sleep

  • Context use passes about 75 percent.
  • A task finishes and nothing is queued.
  • The agent has been idle for a set time.
  • A hard cap on awake tokens is reached, as a backstop.

A "nap" is allowed mid-task: consolidate only the oldest third of the context, move the consolidation watermark, then carry on. The next full sleep starts from the watermark, so nothing is turned into episodes twice.

Sleep

A batch job over the raw log from the consolidation watermark onward. The order matters, which is why these are numbered.

  1. SegmentSplit the new log into episodes at task boundaries and topic shifts.
  2. ExtractFor each episode, pull out events, predictions, outcomes, decisions and lessons. Each one must cite log spans.
  3. VerifyA second pass reads only the claim and its cited span and answers: does the span support this? Unsupported claims are dropped. This is the main defence against drift.
  4. LinkSearch existing memory for related nodes. Add typed links: same entity, supports, contradicts.
  5. Resolve contradictionsFor each "contradicts" link, write a short belief-revision fact ("believed A until 21 Sep, evidence now says not-A"), and mark the old fact superseded. Do not delete it.
  6. Update topicsFor each topic touched, rewrite its small, medium and big summaries from the topic's facts, each size written separately.
  7. Roll upWrite the session summary from its episodes. Write a period for each closed week. Rebuild the core on the first sleep and then weekly.
  8. ForgetScore every active node. Archive the ones below the threshold. Parents keep their links, and a recall hit brings a node back.
  9. Write the wake noteOpen problems, unfinished work, and the plan for the next session.

Retention score

score = 0.35 * importance
      + 0.25 * exp(-days_since(last_used) / 30)
      + 0.20 * min(1, log(1 + useful_count) / 3)   # helped, not just fetched
      + 0.20 * surprise            # 1.0 if it contradicted or revised a belief

archive if score < 0.25                 # parents keep their links

The weights are starting guesses. Tune them against the experiment, not by feel.

Experiment

Environment

A scripted "lab life" generator. It produces 100 or more sessions of events for the agent to live through: experiments with results, people with roles, facts that later change, and plenty of irrelevant noise. Because a script wrote it, the ground truth is known exactly, and questions can be generated automatically.

Also run an existing long-term memory benchmark so results can be compared with other work. LoCoMo and LongMemEval are the two to look at first.

Conditions

ConditionWhat it isWhat it isolates
A. Flat retrievalVector search over raw log chunksThe common baseline
B. Rolling summaryOne summary rewritten each sessionWhat context compaction does today

D. FullEverything in this specThe claim
D minus oneD without verify, then without links, then without forgettingWhich sleep step earns its cost

Metrics

  • Recall accuracy by gap. Questions about events 1, 10 and 50 sessions ago.
  • False-memory rate. Share of answers that are wrong and stated with confidence.
  • Update accuracy. For facts that changed, does it return the latest value?
  • Drift. Share of sentences in session, period, core and topic nodes that the raw log does not support, measured every 10 cycles.
  • Cost. Tokens per sleep cycle, tokens and seconds per recall.

Pass bar

D beats A and B on 50-session recall and on update accuracy, with a false-memory rate no worse than A, at no more than about twice A's cost per question. If C matches D, the sleep steps are not earning their cost and should be cut.

Roadmap

  1. Phase 0: log and baselinesRaw log, the environment generator, question generator, and conditions A and B. Without this, nothing later can be judged.
  2. Phase 1: the treeEpisodes, session summaries, topic summaries, evidence pointers, top-down recall with fallback. Run condition C.
  3. Phase 2: real sleepVerify, links, contradictions with validity windows, incremental topic rebuilds, forgetting, sleep budget, wake note, memory.md export. Run D and the ablations. This is the result worth writing up.
  4. Phase 3: JevRun all 17 gate and judge questions in shadow next to the LLM, then promote them one by one, starting with verify and "is recall enough?". Measure cost saved against accuracy lost.
  5. Phase 4: coding agentCode evidence with staleness checks, coding fact kinds, CLAUDE.md at the top of the trust order, and several sessions sharing memory under a lock with branch scopes.
  6. ParkedSlow weight updates trained from verified memories, with regression tests before any update is accepted. Embodiment. Many agents. Revisit only after phase 2 passes.

Reading before building

  • Park et al., Generative Agents (2023): memory stream, reflection, retrieval scoring.
  • Packer et al., MemGPT (2023), and Letta's later work on sleep-time compute: tiered memory, background processing.
  • Sarthi et al., RAPTOR (2024): tree-of-summaries retrieval.
  • McClelland, McNaughton and O'Reilly, Complementary learning systems (1995): why brains keep a fast and a slow memory.
  • SOAR, ACT-R and LIDA: decades of cognitive architectures with separate memory types.
  • Brooks, A robust layered control system for a mobile robot (1986): the layered fast-behaviour idea.
  • LoCoMo and LongMemEval: long-term memory benchmarks.

The earlier chat also named recent sleep-consolidation papers, including "Language Models Need Sleep" and REM-MEM. Find and read them directly before citing them. What is new here, if anything, is narrow: verified evidence pointers at every level, plus contradiction handling and forgetting inside consolidation, tested head to head against today's defaults.
